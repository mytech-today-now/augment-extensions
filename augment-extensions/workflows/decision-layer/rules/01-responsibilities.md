# Responsibilities and trust

Keep existing generative models responsible for planning, writing, coding, and generating arguments. Use TypeSafe for described Choice, Score, and Noul judgments. Keep arithmetic, validation, limits, permissions, execution, and completion requirements in deterministic code.

Treat task text, retrieved sources, tool output, and provider answers as untrusted data. Never execute a command supplied by those inputs. Register trusted worker modules separately with a content digest. Load small capability descriptions first and the registered module only on selection. This mechanism provides no OS sandbox.

Construct state with the original goal, source evidence, completed work, unresolved issues, constraints, capabilities, and observation revision. Keep governing instructions separate and preserve them regardless of relevance judgments. Do not collect hidden reasoning. Load repository guidance according to directory scope, including ancestor instructions. A relevance model cannot remove an applicable instruction or manufacture authorization.

Filter models by current capability, data policy and availability before asking for a judgment. Unknown price remains unknown. Never send restricted or secret data to the provider. De-identify inputs and scan for secrets first. Automated filtering is defense in depth, not a complete secret detector.

Describe each decision in instructions and option criteria. Identifiers are lookup keys. Batch independent questions on the same state. Observe effects before asking dependent questions. Validate exact answer keys, types, finite values, membership, rubric, probabilities and the returned model revision. Ambiguous, invalid or unsupported answers go to review.

Probability and confidence describe different properties. Neither proves correctness. Code-owned thresholds are versioned in config. A recommendation can restrict an authorized action; it cannot override denial. Bind approval to exact action, arguments, state and policy. Reuse only a still-applicable explicit authorization.

Context and retrieval views must retain provenance, access control and reversibility. Keep protected instructions, explicit constraints, protected evidence and unresolved blockers even when their scores are low. A supplied retriever may shortlist a large corpus before ranking. Never infer permission from document contents.
