# Visual Design Brief

## Purpose

Create a compact, evidence-aware design brief before exploring visual treatments or implementation.

## Usage

1. Identify the product, user groups, context, and primary task. Ask the requester for missing facts when they block a useful result. Mark assumptions instead of inventing research.
2. State the user outcome and product outcome separately. List constraints, supported platforms, existing design systems, accessibility targets, content, localization, and operational dependencies that are known.
3. Map the main journey from entry through successful completion and recovery. Note service handoffs, support, notifications, and offline or interrupted states when they apply.
4. List open questions with the evidence needed to answer them. Choose a method that fits the question, such as observation, interview, usability test, survey, or analytics review.
5. Describe two or more design directions only when they resolve a real tradeoff. Compare user value, accessibility, platform fit, effort, and risks.
6. Define how the selected direction will be evaluated. Choose observable measures such as task completion, errors, comprehension, or a relevant product outcome.
7. Link the [coverage map](../guidelines/coverage-map.md) and applicable rules. For screen interfaces, include responsive validation in the test plan.

## Output

Provide:

- Users, context, primary tasks, and intended outcomes.
- Evidence, assumptions, unknowns, and limitations.
- Journey, key states, and service touchpoints.
- Constraints and design-system or platform dependencies.
- Design options and explicit tradeoffs.
- Validation method, observable measures, and next decision.

Do not report unrun research or measured results as facts.
